Codex Skill / Talking Head Workflow

我做了一个专门剪口播的 Codex skill

不是又一个 AI 剪辑概念。

而是一个很具体的本地工作流。

输入口播视频和文案，直接输出可交付的 MP4。

口播视频一直有一个很典型的问题。

拍摄本身不难，真正耗时间的是后处理。

剪气口、铺字幕、挑重点词、补音效、垫 BGM、导出成片，这些动作单个都不复杂，但它们足够碎，足够高频，也足够消耗人。

如果你长期做内容，这种消耗会非常明显。

它不会一下把你拖垮。

但会稳定地吃掉你的时间、注意力和表达欲。

所以我这次做的，不是一个泛泛的 AI 剪辑工具，而是一个目标非常明确的本地 skill。

输入一段口播视频。

再输入一份对应文案。

最后直接产出 MP4。

不生成草稿。

不要求回到剪辑软件继续收尾。

不把最烦的最后一步留给人。

这个 skill 在解决什么问题

我把它想解决的问题压缩成三件事。

1. 口播最烦的不是剪辑本身，是重复劳动

很多流程不是不会做，而是不值得一直手工做。

尤其是口播，真正消耗人的不是复杂转场，不是高级特效，而是反复听，反复剪，反复校对，反复把一句话修顺。

这种劳动没有技术门槛上的成就感，但它又绕不过去。

2. 现有自动化经常只做到一半

很多方案可以帮你生成草稿，或者做一个基础时间线。

但真正能发出去的视频，往往还差最后一层处理。

字幕样式要收。

重点信息要提。

音效和 BGM 要跟。

最后还要导出成片。

问题就在这里。

对创作者来说，草稿不是结果。

MP4 才是结果。

3. 很多方案只适合样例，不适合长期复用

今天能剪汽车口播。

明天换成 AI 工具评测。

后天换成课程视频。

如果每换一个题材就要重写一套逻辑，那它沉淀下来的只是案例，不是能力。

我想做的是一套能稳定服务不同口播内容的处理逻辑。

我具体做了什么

这个 skill 的目标很直接。

把从素材到成片这条链路，尽可能一次走完。

它接收两个核心输入。

  • 原始口播视频
  • 对应文案

然后自动完成后面的流程。

  1. 识别视频横竖屏，自动确定渲染方向
  2. 做音频和文案对齐，优先拿词级时间戳
  3. 基于词间间隔规划气口剪辑
  4. 重建字幕和关键词时间线
  5. 根据文案语义给重点词分类型
  6. 生成花字、音效、BGM 的渲染计划
  7. 用 Remotion 输出最终 MP4

你可以把它理解成一个本地的口播成片流水线。

不是生成辅助信息。

而是直接生成视频结果。

这套架构为什么这样设计

整个 skill 最核心的架构，其实是两个判断。

一个判断是，口播剪辑的关键不在句子级，而在词级。

另一个判断是，成片这件事不能停在时间线，必须走到最终渲染。

词级对齐，是这条链路的地基

很多人对自动剪口播的理解，是先识别字幕，再删掉句子之间的空白。

这不够。

因为中文口播最影响观感的停顿，很多发生在句子内部。

说到一半停一下。

重复一下。

卡一下。

插一个语气词。

这些细碎的问题，如果还是按整句处理，很多会漏掉。

所以我这里优先走火山音字对齐，拿词级时间戳。

如果没有相关鉴权，再退回本地 Whisper。

这样做的原因很简单。

口播剪辑最值钱的地方，不是识别出了什么字。

而是能不能拿到足够细的时间信息，去修说话节奏。

一旦拿到词级时间线，很多判断都会变得可靠。

上一个词什么时候结束。

下一个词什么时候开始。

中间空了多久。

这一段到底该不该剪。

这时候你处理的就不再是文本块，而是节奏本身。

最终渲染，必须和剪辑本身放在一条链路里

这个 skill 没有停在 clean video。

因为 clean video 不是成片。

真正的视频交付，还包括字幕、重点词强调、音效、BGM 和最终导出。

所以我最后选了 Remotion 来负责渲染层。

底层用 Python 和 ffmpeg 做确定性的媒体处理。

上层用 Remotion 做视觉和声音编排。

前一层负责把素材整理成干净、可描述的数据。

后一层负责把这些数据真正变成一个能发出去的视频。

拆开来看，这套架构会更清楚。

底层处理层

  • 校验输入文件
  • 探测视频方向和尺寸
  • 抽取音频
  • 跑对齐
  • 生成词时间线
  • 检测气口和卡壳
  • 裁剪并拼接 clean video
  • 重建字幕
  • 输出 render manifest

渲染输出层

  • 烧录字幕
  • 渲染关键词高亮
  • 安排音效和 BGM
  • 输出最终 MP4

为了泛化，我没有按行业写死规则

这是这次设计里另一个比较重要的点。

一开始最容易想到的方式，是按行业做高亮规则。

比如汽车视频抓价格、配置、车型、安全。

但这套东西一旦离开样例，马上就会变脆。

所以后来我把重点词处理，改成按语义角色分类。

  • 实体
  • 数字
  • 利益
  • 证明
  • 风险
  • 行动
  • 情绪

这样一来，汽车视频里的续航数字，AI 产品里的生成时长，课程视频里的七天计划，虽然内容不同，但承担的是同一种表达功能。

这时候被沉淀下来的，才是一套可复用的能力。

我还补了几个很实际的细节

很多工具停在 demo，是因为它们没把细节做进链路里。

这个 skill 里我补了几个会直接影响成片体感的点。

字幕样式收了

我把半透明底纹去掉了，字号也收小了。

原因很简单，口播视频里最重要的还是人本身，字幕不能喧宾夺主。

花字定位不再跟着字幕行数跑

之前有个很烦的问题。

字幕从一行变两行的时候，花字会被顶上去，画面会跳。

后来把花字位置独立出来，这个问题才真正解决。

声音层被纳入主链路

如果只有画面，没有一点点关键词音效和 BGM，最终成片会少一口气。

所以我把音效和 BGM 也纳入了这条链路里，而且优先使用本地整理好的素材索引，而不是每次临时联网搜索。

原因也很现实。

长期可用的生产系统，稳定比花哨更重要。

这个 skill 最后解决了什么

做到现在，我觉得它至少解决了三个现实问题。

第一，把最容易让人疲惫的重复劳动收进去了一大块

以前你要自己反复听、反复剪、反复铺字幕、反复调关键词。

现在这些步骤至少可以先自动跑出一个完整版本。

第二，把自动化从半成品推进到了成片

这件事很重要。

因为草稿不是结果。

成片才是结果。

只有直接拿到 MP4，这套自动化对创作者来说才有真正价值。

第三，把经验沉淀成了可复用的生产环节

今天剪一条口播。

明天再剪另一条。

只要输入形态差不多，这套流程就还能继续复用。

这就不是一次性的手工操作，而是一个可以反复调用的工作流。

实际用起来怎么样

它现在的使用方式很简单。

你准备一段原始口播视频。

再准备一份对应文案。

把这两个输入交给 skill。

剩下的流程它自己走。

如果本地有火山鉴权，就优先走词级对齐，气口会剪得更细。

如果没有，就退回本地 Whisper，但精度会降一档。

最后除了成片，它还会保留 alignment、cut plan、manifest、highlight plan 这些中间产物。

这点我也很看重。

因为真正能长期用的工具，不是一次给你一个神奇结果。

而是它既能跑通，也能继续调。

最后

坦率地讲，这个 skill 现在还是 MVP。

它不是银弹。

也不是说从今天开始，所有口播视频都可以完全不用人碰。

但它已经把一条最烦、最碎、最适合被自动化的链路，先打通了。

对我来说，这就足够重要。

因为很多时候，工具真正有价值的地方，不是一步登天。

而是先把一个足够具体、足够高频、足够折磨人的问题，认真解决掉。

这个口播剪辑 skill，就是这样一个东西。

如果你也长期做内容，我相信你会知道，这类小问题一旦被解决，带来的轻松感，往往一点都不小。
